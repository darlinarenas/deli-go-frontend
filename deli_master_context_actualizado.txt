============================================================
ESTADO GENERAL DEL PROYECTO
============================================================

DELI GO / DELIFOODS es una plataforma de delivery pensada inicialmente para Punto Fijo, Falcón, Venezuela, con intención de escalar luego a otras ciudades.

La idea es construir una plataforma tipo PedidosYa / Uber Eats, con:
- Clientes.
- Restaurantes.
- Repartidores.
- Administrador del sistema.
- Pagos adaptados a Venezuela.
- Ubicación GPS obligatoria para entregas.
- Flujo especial para enviar comida a otra persona.

Actualmente el frontend está avanzado y funciona en HTML, CSS y JavaScript vanilla.

Estructura base del proyecto:
- index.html
- mis-pedidos.html
- vista pública del restaurante
- panel-restaurante.html
- css/styles.css
- css/restaurant.css
- css/panel-restaurante.css

ACTUALIZACIÓN 26-04-2026 - BUSCADOR, CATEGORÍAS Y DATOS
============================================================

Hoy se resolvió un bloqueo importante relacionado con el index, el buscador y la lectura de platos desde backend.

Problema detectado:
- El index mostraba restaurantes, pero al buscar platos como “pizza” no aparecían resultados.
- Las categorías dinámicas no se mostraban completas.
- Solo aparecían botones como “Todos” y “Comida”.
- El backend sí tenía endpoint para platos, pero el frontend no podía relacionar correctamente restaurantes con platos cuando los datos estaban inconsistentes.

Causa real encontrada:
- El problema principal no era el frontend.
- El problema estaba en la consistencia de datos dentro de dishes.json.
- Un plato tenía restaurantEmail mal guardado en formato de enlace tipo:
  "[medanos@gmail.com](mailto:medanos@gmail.com)"
- El backend compara emails limpios.
- Por eso /restaurants/medanos@gmail.com/dishes devolvía total 0.
- Al limpiar el email y dejarlo como "medanos@gmail.com", el plato fue encontrado correctamente.

Resultado logrado:
- El endpoint de platos por restaurante funciona.
- El sistema ya puede asociar platos con su restaurante correcto.
- El index ya puede mostrar resultados de búsqueda por platos.
- Las categorías dinámicas ya se generan desde los platos reales agregados por los restaurantes.
- Cuando un restaurante agrega una categoría/plato nuevo, la categoría puede aparecer automáticamente arriba como filtro.
- El buscador quedó mejorado y funcionando correctamente sobre el archivo real restaurants.js.
- El usuario confirmó que el buscador quedó perfecto.

Estado actual del buscador:
- Busca por restaurante.
- Busca por plato.
- Busca por descripción del plato.
- Busca por categoría del plato.
- Muestra el restaurante y el plato relacionado.
- Mantiene las categorías dinámicas.
- Mantiene la estructura visual existente.
- No se deben rehacer estos cambios desde cero.

Regla importante aprendida:
- Si un plato no aparece, antes de cambiar código se debe revisar:
  1. Que el plato exista en dishes.json.
  2. Que restaurantEmail del plato sea exactamente igual al email del restaurante.
  3. Que el endpoint /restaurants/:email/dishes devuelva total mayor a 0.
  4. Que el backend esté leyendo el archivo correcto.
- No modificar restaurants.js a ciegas si el endpoint devuelve total 0.
