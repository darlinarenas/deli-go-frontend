BHUZ 247 - PARCHE CONSERVADOR
Fecha: 2026-07-19

OBJETIVO
- Reutilizar para comida el mismo principio estable de paquetes: código directo de 6 dígitos guardado en PostgreSQL y validado por el panel repartidor.
- Usar un único service worker compartido por usuario y repartidor para las notificaciones push.
- No eliminar ni reemplazar módulos funcionales.

HALLAZGOS
1. El código de comida ya se genera al crear el pedido y se guarda en orders.delivery_code.
2. El panel repartidor ya valida FOOD_ORDER y PACKAGE desde el mismo modal y endpoint de trabajos.
3. El ZIP de producción no contenía service-worker.js, aunque js/pwa.js intentaba registrarlo.
4. El repartidor podía continuar recibiendo avisos por un service worker antiguo conservado en su dispositivo; una instalación nueva del usuario no tenía ese archivo.

CORRECCIONES
- Se agregó service-worker.js compartido para usuario y repartidor.
- El service worker recibe push, muestra la notificación y abre la pantalla correspondiente.
- HTML, JS y CSS usan red primero para evitar versiones viejas atrapadas en caché.
- Se actualizó la versión PWA de 20260719-8 a 20260719-9.
- Se conservaron todos los HTML, JS, CSS y módulos del ZIP original.

CÓDIGO DE ENTREGA DE COMIDA
- Tabla: orders
- Campo principal: delivery_code
- Generación: al crear el pedido en createOrderInPostgres.
- Lectura cliente: GET /orders/me o /orders/customer/:email.
- Cierre repartidor: POST /api/drivers/:driverId/jobs/:jobId/confirm-delivery.
- El mismo modal del repartidor se usa para PACKAGE y FOOD_ORDER.

DESPLIEGUE OBLIGATORIO
1. Vercel: desplegar el frontend completo, incluyendo service-worker.js en la raíz.
2. Render: desplegar deligo-backend de este mismo ZIP.
3. En el teléfono, desinstalar el PWA anterior, borrar datos del sitio e instalar otra vez.
4. En iPhone, abrir desde el icono agregado a Inicio para solicitar notificaciones.

ARCHIVOS CAMBIADOS/AGREGADOS

- js/pwa.js
